赛题 T04 语音模型适配 ｜ 卡型 K100-AI（K500SM_AI 64GB 单卡）｜ vLLM 0.21.0 ｜ bf16

1. 简介

本报告记录 Qwen3-ASR-1.7B、Qwen3-ASR-0.6B、Qwen3-ForcedAligner-0.6B 三个语音模型在 海光 K100-AI（实测实例 K500SM_AI 64GB 单卡）上的适配与优化结果，覆盖语音识别（转写）与强制对齐（词级时间戳） 两类任务。

核心结论：三个模型均在该卡上跑通并给出可复现的实测数据，未修改任何模型代码、未升级任何软件包， 全部复用镜像自带的 HCU 版 torch / triton / vllm-hcu 与 DTK；适配工作集中在运行时装配与三个启动参数的确定上。

关键实测：单并发下 Qwen3-ASR-1.7B 达 21.97 倍实时、32 并发达 208 倍实时；0.6B 分别为 37 倍与 225 倍实时； 强制对齐模型对 7.18 s 英文音频输出 16 个词级时间戳、对 5.62 s 中文音频输出 13 个逐字时间戳，均严格单调且落在音频时长内。

提交仓库：https://github.com/devinhuang2001/hygon-hackathon-2026
仓库内 submissions/01、02、08 三个目录即为本报告对应的完整提交包（含脚本与原始证据）。

3. 适配优化方案

3.1 基础镜像与软件包

使用 docker_images.md 中 vLLM 0.21 的推荐镜像；未升级任何软件包，requirements-extra.txt 为空。 镜像自带 torch / triton / vllm / vllm-hcu / flash_attn / aiter / lmslim 全套海光版本。

3.2 三个必须处理的运行时装配

现象根因处理
ModuleNotFoundError: vllm...fused_moe.modular_kernel 镜像内 vllm_hcu 用绝对符号链接覆盖 vllm 的部分模块，解包后指向 /usr/local/... 失效 把指向镜像绝对路径的链接改指向 $ROOTFS 同一路径（run.sh 内幂等执行）
get hyhal driver version error / hcusmi 初始化失败 镜像不含 /opt/hyhal（驱动用户态由平台注入，等同 nvidia-container-toolkit） 补入宿主 /opt/hyhal，并放进 LD_LIBRARY_PATH
HSACOError: File operation failed: ... .amdgcn，表现为 EngineCore 启动失败 triton 的 HCU 后端从 ROCM_PATH 下找 aillvm；宿主 DTK 无该目录，回退到 llvm 导致编译产物缺失 ROCM_PATH 指向镜像内 DTK（含 aillvm），驱动仍用宿主 /opt/hyhal

3.3 强制对齐模型的三项专属设置

Qwen3-ForcedAligner-0.6B 的 config.json 中标称 architectures=Qwen3ASRForConditionalGeneration， 但实际是 token classification 头。三项设置缺一不可，否则分别报「按生成模型加载失败」「走生成路径」「max_model_len 校验失败」：

--runner pooling
--hf-overrides '{"architectures":["Qwen3ASRForcedAlignerForTokenClassification"]}'
--max-model-len 8192        # 模型 max_position_embeddings 上限，写 32768 直接报错

官方用 qwen_asr 包的 Qwen3ForcedAligner.align()；本环境无该包（PyPI 镜像亦无）， 故按官方源码 qwen_asr/inference/qwen3_forced_aligner.py 逐段复刻算法到 vLLM pooling 路径：

  • 输入构造：<|audio_start|><|audio_pad|><|audio_end|> + "<timestamp><timestamp>".join(words) + "<timestamp><timestamp>"
  • 取 timestamp_token_id=151705 位置的分类 argmax，时间(ms) = 索引 × timestamp_segment_time（本模型 80 ms/格）
  • 用最长递增子序列平滑异常跳变后，按 (start, end) 成对切给每个词；中文按官方 CJK 规则逐字切分

3.4 升级步骤

解包镜像 → bash run.sh（装配环境 + 起服务 + 轮询 /health）→ bash env_check.sh → bash smoke.sh → bash bench.sh

4. 服务启动脚本

4.1 语音识别（两个 ASR 模型，仅模型路径不同）

python3 -m vllm.entrypoints.openai.api_server \
  --model /root/hygon/models/asr_orig \
  --served-model-name qwen3-asr-1.7b \
  --trust-remote-code --dtype bfloat16 \
  --max-model-len 32768 --gpu-memory-utilization 0.90 \
  --host 127.0.0.1 --port 8000

参数理由：--dtype bfloat16 与官方权重一致、匹配镜像内 flash-attn 路径；--max-model-len 32768 为模型原生上下文（单条音频远小于此，KV cache 按实际长度分配）；--gpu-memory-utilization 0.90 单卡独占， 留 10% 给 DTK 运行时与编译缓存，实测稳态显存 60.2 GB / 64 GB；未开 --enforce-eager，走默认 torch.compile + CUDA Graph（首次启动一次性编译，缓存可复用）。

4.2 强制对齐

python3 -m vllm.entrypoints.openai.api_server \
  --model /root/hygon/models/fa06 \
  --served-model-name qwen3-forcedaligner-0.6b \
  --runner pooling \
  --hf-overrides '{"architectures":["Qwen3ASRForcedAlignerForTokenClassification"]}' \
  --trust-remote-code --dtype bfloat16 \
  --max-model-len 8192 --gpu-memory-utilization 0.35 \
  --host 127.0.0.1 --port 8000

--gpu-memory-utilization 0.35 足够（0.6B 分类头 + 长音频 KV），留余量便于与其它模型共用一张卡。

8. 注意事项

  • -hf 后缀的 ASR 权重不能用：Qwen3-ASR-1.7B-hf 的 707 个张量全部带 model. 前缀， vLLM 0.21 加载报 ValueError: There is no module or parameter named 'model'。必须用非 hf 版 （thinker. 前缀）。这一点会浪费大量排查时间，建议写进官方文档。
  • 三个装配缺一不可：符号链接重指向、补 /opt/hyhal、ROCM_PATH 指向镜像内 DTK。 第三个最隐蔽——现象是 EngineCore 启动失败，容易误判为「模型不支持」。
  • 纯文本请求不能当文本模型用：ASR 模型收到无音频的文本请求会返回 <asr_text> 类空结果， 接口可用但语义无意义。
  • 音频必须解码成数组传入：vLLM 的 multi_modal_data={"audio": path} 传字符串会抛 AssertionError ... got: '/'；且镜像内 torchaudio.load 因缺 torchcodec 不可用， 用 ffmpeg -f f32le -ac 1 -ar 16000 管道解码最稳。
  • 时间戳掩码要按后缀对齐：音频占位符会在引擎侧展开（本例预测 148 个位置、纯文本 52 个）， 按纯文本 token 数取位置会取错；早期写法能出数但同一句音频起点会从 1.12 s 漂到 2.96 s。
  • 首次启动耗时不是卡死：ASR 约 2–5 分钟（torch.compile）；强制对齐在 enforce_eager 下仅 8.7 s。 建议用「轮询 /health + 进程存活检查」代替固定 sleep。
  • aiter 会提示 NUMA balancing is enabled, which may cause errors，本实例无权限写 /proc/sys/kernel/numa_balancing，实测未影响结果，保留原样。
