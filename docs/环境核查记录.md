# 国芯国模黑客松 — 材料核查与可行性结论

核查时间：2026-10-30。来源：飞书 wiki 文档（已全文导出）+ GitHub `HYGON-AI` 组织 + SCNet 共享实例实测。

## 一、结论先行

1. **文档能全文读出来**，不止前两节。赛题清单、验收标准、技术报告 8 章节、官方 14KB 报告模板都已落到 `official/`。
2. **官方赛题是 18 个固定模型**，和 cookbook 的 45 行支持矩阵**基本不重叠**——只有 3 个模型同时出现在两边。把矩阵空格当成"待认领件"会跑偏。
3. **卡型完全对得上**：实例是「异构加速卡AI 64GB」，官方明确 `K500-SM 按 K100-AI 计`。
4. **但这一台实例跑不了任何一件**：没有 vllm/sglang、没有容器运行时、没有外网、没有赛题权重和官方基线。任何 `✅` 都无法凭实跑产出。

## 二、官方口径（文档正文，非推断）

- 计件粒度 = **模型 × 卡型 × 框架**；卡型不同各算一件；量化版（INT8/INT4）单独计件。
- 硬件只有两档：**异构加速卡 BW** 与 **异构加速卡 AI-64GB**，其它不算。
- 门槛：精度先达标。基线取官方 GPU 结果，**较基线劣化 ≤2%**；评测参数在官方基线文件里写死，参赛者不得修改。
- 可复现：干净环境一键复跑，**偏差 >20% 打回**。
- 反作弊：改权重/结构/tokenizer/采样语义、硬编码答案、**伪造日志** → 取消资格。
- 提交物 = 一份技术报告（8 章节，作为仓库 `README.md`）+ 一个代码仓库（含 `env.sh`/`run.sh`/`smoke.sh`/`verify.py`/`bench.sh` 及其原始产出）。报告里的版本号与数字必须与 `env.log`、`verify_result.json`、`bench/round2.jsonl` 一致。

官方赛题 18 个模型（T01 文本 / T02 视觉 / T03 生成 / T04 语音，明细见 `official/赛题清单.md`）。把它们逐个对照 cookbook 矩阵：

|---|---|---|
| Qwen3-ASR-1.7B | 有（`Qwen3-ASR` vLLM） | `-` 空 |
| Qwen3-ForcedAligner-0.6B | 有（`Qwen3-ForcedAligner` vLLM） | `-` 空 |
| Wan2.1-I2V-14B-480P | 有（`Wan2.1-I2V`，3 个框架） | 三格全 `-` |
| Kimi-Linear-48B-A3B / MiMo-V2.6-Distill-Qwen-9B | 无（矩阵只有 Kimi-K2/K2.5/K2.6/K3、MiMo-V2.5-Pro/V2-Flash） | — |
| DeepSeek-V4.1-Flash-1017 / DeepSeek-V4-Flash-Vision-Exp | 无（矩阵是 `DeepSeek-V4`） | — |
| MiniMax-M3.1-Flash | 无（矩阵是 `MiniMax-M3`） | — |
| Kimi-VL-A3B、MiniCPM-V-4.7-35B-A3B、RoboBrain2.5-8B-NV、MobileVLA-R1、Recon2Reason-Reasoning-4B、Trident-Qwen3VL-2B、Qwen-Image-2.1-Turbo、HY-OmniWeaving、MiniMax-Music3、HY-World-2.0、AuK | 全无 | — |

也就是说：**只有 3 个赛题模型在矩阵里有现成文档可对照**，其余 15 个都是从零开始（要先让它跑通，再谈文档）。反过来，矩阵里那 40 多个模型（Qwen3-VL、GLM-5.x、Kimi-K2.x…）大多不在赛题清单里，对计件没用。

矩阵全局统计：91 行（模型×框架）× 3 卡型 = 273 个状态值，其中 `✅ 115`、`-` 103、`🚧` 43、`文档` 12。
单看 K100_AI 一列：91 格里 `✅` 只有 17 个，`-` 52、`🚧` 22。

## 四、"已完成"的状态要分清

- **真正已验证（✅）**：可当参考抄结构，如 `vllm/deepseek-r1.md`、`sglang/qwen3.8.md`。
- **只有文档没验证（`文档`，12 格）**：`Qwen3-VL` BW1100、`Qwen2-72B` BW1100、`GLM-5.3` BW1100、`Hy3` BW1000、`Kimi-K2.6` BW1000+BW1100、`Kimi-K2.5` BW1000、`MiniMax-M3` BW1000、`Step-3.7-Flash` BW1000+BW1100、`MiMo-V2-Flash` BW1000+BW1100。**这些不能当"已完成"算**，卡型列还没实测。
- **`🚧` 43 格**：别人在做，别碰（如 `Qwen3-VL` vLLM K100_AI、`DeepSeek-V4` K100_AI、`GLM-5.1/5.2` K100_AI）。

K100_AI 这一列 91 格里 74 格不是 ✅——单看矩阵空间很大，但受下面这条限制。

## 五、这台实例为什么跑不了（实测证据）

实例：`ksai.scnet.cn:10667`，Hygon C86 7185 32c / 503G / 1×**K500SM_AI 64GB**，DTK 6.3.26113，`NOTEBOOK_ACCELERATOR_MODE='DCU：异构加速卡AI 64GB,1'`（正好是赛题的 AI-64GB 档）。

| 需要的东西 | 实测结果 |
|---|---|
| vllm / sglang + das 插件 | `pip list` 命中 0 条，只有 torch 2.10+das、flash_attn、triton、transformers 5.17 |
| 容器运行时（跑官方镜像） | `docker`/`podman`/`apptainer`/`singularity` 全无 |
| 外网（装包/下模型/拉镜像） | 全断：连 `223.5.5.5:53`、`www.scnet.cn:443`、`developer.sourcefind.cn:443` 全部 timeout；`apt update` 全挂 |
| 赛题模型权重 | 共享池只有 `Qwen1.5-7B-Chat`、`Yi-34B-Chat`、`gemma-2b`、`glm-4v-9b`（2024 年的老模型） |
| 官方基线 `baselines/<模型>.json` + `data/` 评测子集 | `/public`、`/root/private_data` 全盘 find 无命中 |

结论：**能写文档，不能出证据**。而验收要 `verify.py` 现场跑分、官方复跑、偏差 >20% 打回，凭"看文档推出来的命令"标 ✅ 属于伪造，红线。

## 六、缺的四样官方材料（拿到就能开工）

1. **官方基础镜像**（含 DTK + vllm-plugin-das / sglang-das，开箱即用）——SCNet 镜像库 `https://www.scnet.cn/ui/aihub/image` 选，或控制台建实例时选推理镜像。
2. **赛题模型权重**——超算互联网 AI 社区下载到数据盘（`/public/home/<user>`）。
3. **`baselines/<模型>.json`**（写死子集题数、max_tokens、思考开关、GPU 基线分数）——随分题材料下发，没有的按文档说"群里沟通"。
4. **`data/` 评测子集**——同上。

**我能立刻做（不需要跑）**：按 `add-model` 规范产出 cookbook 文档草稿、按官方模板产出技术报告 8 章节骨架、把 `env.sh` 的参数按目标模型填好。但这些只能停在"待验证"，不能标 ✅。

## 八、两处口径冲突（提交前要注意）

- 赛事 `run.sh` 模板用 `python -m sglang.launch_server`，而 cookbook `CONTRIBUTING.md` 明确要求 `sglang serve`、不要用已废弃的 `launch_server`。**提交仓库按赛事模板，cookbook 文档按 CONTRIBUTING**——两份产物两套规矩。
- 赛事文档 `CARD` 变量注释写 `BW1000 | K100-AI（K500-SM 按 K100-AI 计）`，写报告时卡型填 `K100-AI`；cookbook 表格里则用 `K100_AI`（下划线）。

## 十、官方模板本身有个缺陷（照抄会踩）

wiki 里那 6 个脚本**在文档源头就是粘连的，不是导出问题**。原文实测：

```
#!/usr/bin/env bash# 采集验证环境写入 env.log；…直接取自这里# 在 run.sh 之后执行…实际生效的版本source ./env.sh
{
  echo "image: $IMAGE"echo "dtk: $(cat /opt/dtk/.info/version …)"
```

shebang 被并进了注释行（`bash` 后面直接接 `#`），多条 `echo` 粘在一行，`source ./env.sh` 也粘在注释尾部。按原样另存为 `.sh` 会语法错误或静默丢步骤。

所以：**别从 wiki 手抄脚本**，从任务池/分题材料拿官方下发的脚手架原件；如果只能靠 wiki，至少把每个脚本按语句边界补回换行后用 `bash -n` 过一遍。同理 `verify.py` 的 `return text.split(...)` 与 `def` 之间、`bench.sh` 的 `done# 第二次…` 都粘在一起。

## 十一、环境已打通（已实跑，2026-10-30）

上一节说的"跑不了"已被解决——不依赖容器运行时，把官方镜像搬进 Notebook 里跑起来了。

**做法**：harbor 匿名拉 `hcu/admin/base/vllm:0.21.0-ubuntu22.04-dtk2604-py3.10` 的 24 层（7.87 GB）→ 传到实例解包成 `/root/hygon/rootfs`（31 GB）→ 用宿主内核视图 + 镜像内包/DTK 运行（`mount` 被禁，chroot 缺 `/sys`、`/proc` 会导致 SMI 初始化失败，所以不走 chroot）。

**踩到的三个坑**（都已解决，写进报告第 3 节）：

1. `vllm_hcu` 用**绝对符号链接**覆盖 `vllm` 的模块，解包后指向失效 → `ModuleNotFoundError: ...modular_kernel`。改指向 rootfs。
2. 镜像**不含 `/opt/hyhal`**（驱动用户态由平台注入，等同 nvidia-container-toolkit），要补。
3. triton 的 HCU 后端要 `ROCM_PATH` 下有 `aillvm`，宿主 DTK 没有 → 报 `HSACOError: ... .amdgcn`。把 `ROCM_PATH` 指向镜像内 DTK。

**实跑结果**：vLLM 0.21.0+das 加载 Qwen3-ASR-1.7B 成功，`/health` 200，转写正确
（英文样例逐字正确、中文样例正确），单卡吞吐 22× 实时（并发 1）→ 208× 实时（并发 32）。

**同时确认一个权重坑**：`Qwen/Qwen3-ASR-1.7B-hf` 的 707 个张量全带 `model.` 前缀，vLLM 0.21 直接
`ValueError: There is no module or parameter named 'model'`；必须用 `Qwen/Qwen3-ASR-1.7B`（`thinker.` 前缀）。

产出：`repo-qwen3-asr/`（可提交的仓库骨架 + 真实日志）、`cookbook-patch/qwen3-asr-K100_AI.md`（补矩阵 K100_AI 一格）。

**仍缺**：官方 `baselines/*.json` 与 `data/` 子集 → 精度无法自证，第 6 节留空不编造。

## 十三、远程安全处理（公共实例）

SCNet 实例是公共环境，本轮按「能加密就加密、能删就删」处理：

- 工作目录 `/root/hygon` 建好后立刻 `chmod 700`（`/root` 自带 700），杜绝同机其他账号读取。
- `lock.sh` / `unlock.sh` 两个脚本：把整棵树 `tar | openssl enc -aes-256-cbc -pbkdf2 -iter 100000`
  压成单个 `/root/hygon.enc`，然后 `find -type f -exec shred -u -z` 粉碎明文再删目录；
  需要继续工作时 `unlock.sh` 还原。
- 密钥 43 字符，只在本地 `D:/tmp/keys/hygon.key`，通过 `HYGON_PASS` 环境变量注入 ssh 命令，
  **不写进远程任何文件**。
- 收尾：先 `lock` 再连 `.enc` 一起删，最后核对 `df` 与端口确认无残留。

注意：运行时明文必须存在（镜像 rootfs 32 GB、权重、日志），所以「全程加密」做不到；
能做的是**权限收紧 + 空闲即加密 + 结束彻底粉碎**。
